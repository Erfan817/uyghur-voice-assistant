# Gülnaz · 维语语音助手

> **گۈلناز** —— 给家里长辈用的维吾尔语 AI 对话助手。按下说话，松开就答。

**状态：规划阶段（2026-10）· 代码未开始**

---

## 名字

**Gülnaz（گۈلناز）**：gül（花）+ naz（温柔、娇媚），维吾尔族常见的女性名。

选一个人名而不是工具名，是因为它不该像个翻译器——它更像家里多了一个能说话的伴。长辈叫得出口，才不会觉得是在"用一个软件"。

这个名字同时定下了产品人格：**中年女性、语速偏慢、语气温和、不抢话**。TTS 选型按这个气质走；有条件时用家人熟悉的声音做 zero-shot 克隆，比任何"标准播音腔"都更容易被接受。

## 为什么做这个

维吾尔语使用者超过一千万，但到今天没有一个"豆包级"的维语对话产品：

- 豆包支持 22 种语言、4 种中文方言（粤语/四川话/东北话/陕西话），**没有维吾尔语**
- 市面上的维语 App（维语翻译官、维语翻译通）全是**翻译器**：说一句、译一句、结束。不能追问、没有上下文、不能聊天
- 底层零件其实在 2025–2026 年刚被补齐：维语 ASR（阿里云/讯飞）、维语 TTS（qwen3-tts-uyghur、SLED-TTS）、维语语义模型（CINO）

**缺的不是模型能力，是把它们组装成一个能连续对话的产品。**

而这个产品的第一批用户，就是我家里的长辈：维语是母语、汉语能听不太会说、手机只会用微信和看视频、不会注册账号也不会配置任何东西。对他们来说，语音不是"一种交互方式"，是唯一的入口。

## 目标用户

第一版只服务一类人：**家里的维语长辈**。

| 维度 | 描述 |
|---|---|
| 年龄 | 40–80 岁 |
| 语言 | 维语母语，汉语听说弱，不认汉字 |
| 设备 | 安卓手机为主，屏幕不大 |
| 习惯 | 微信、短视频；不会安装/注册/授权 |
| 诉求 | 问天气、问身体和吃药、闲聊、让 AI 念一段内容、问办事流程 |

不做"所有维语使用者"，先把这一小撮人服务到愿意每天打开。

## 产品原则

1. **三个动作以内说完一句话** —— 打开 → 按住 → 说完
2. **语音进、语音出** —— 屏幕上的字只是辅助，不要求阅读
3. **打开就能用** —— 不登录、不设置、不选音色、不填 API Key
4. **大** —— 大按钮、大字体、高对比度；按下有"我在听"的明确反馈
5. **窄** —— 不追求全能，先把 5 件高频事做好；答不上来就说答不上来

## 技术架构

两条候选链路，先用真实问题做 A/B，再定。

**方案 A · 直连**

```mermaid
flowchart LR
    A[维语语音] --> B[维语 ASR]
    B --> C[LLM 直接用维语回答]
    C --> D[维语 TTS]
    D --> E[播放]
```

链路短、延迟低；但通用 LLM 的维语能力弱，容易夹汉语词、语序怪、术语崩。

**方案 B · 汉语中转（pivot）**

```mermaid
flowchart LR
    A[维语语音] --> B[维语 ASR]
    B --> C[维→汉翻译]
    C --> D[LLM 用汉语推理与回答]
    D --> E[汉→维翻译]
    E --> F[维语 TTS]
    F --> G[播放]
```

链路长、延迟高；但每一环的质量都能单独调，且能复用成熟的中文能力与提示词。

**决策方式**：拿 20 个家里人真会问的问题跑两条链路，3 位母语者盲听打分，选可懂性和自然度综合更高的那条。这一步的结果同时决定了整个项目的技术路线。

## 组件选型

| 环节 | 候选 | 备注 |
|---|---|---|
| 维语 ASR | 阿里云智能语音（控制台可选维语）、讯飞 | 商用 API，按量计费；开源方案对维语支持差 |
| 维→汉 / 汉→维 翻译 | Qwen3、Hunyuan-MT-7B、DeepSeek | 需实测；维语 SOV 语序与汉语 SVO 差异大，直译会出戏 |
| 对话 LLM | Qwen3 / DeepSeek | 中文能力强；维语直接生成质量待评 |
| 维语 TTS | `anke01/qwen3-tts-uyghur`、`ElgekAI/SLED-TTS-Uyghur-UAS-0.2B` | 后者支持 zero-shot 音色克隆，可做"熟悉的声音" |
| 客户端 | 安卓 Kotlin 或 Flutter | 首版只做安卓；PWA 作为退路 |
| 服务端 | 轻量 Python 服务（FastAPI） | 转发 ASR/LLM/TTS，管理提示词与兜底 |
| 部署 | 一台小云主机 | 国内节点，降低往返延迟 |

## 里程碑

### M0 · 链路验证（1 周）

- [ ] 20 个真实问题的语料集（家里人实际会问的）
- [ ] 跑通 ASR → LLM → TTS 的最小链路（不做 UI）
- [ ] 方案 A / B 对比，母语者盲听打分
- [ ] **决策点：翻译质量过不了关就停，不往下做**

### M1 · 可用的 MVP（3–4 周）

- [ ] 安卓 App：单页、大按钮、按住说话、自动播放
- [ ] 首次启动 3 步内可用（无登录）
- [ ] 兜底策略：医疗/宗教/政策类问题的安全回复模板
- [ ] 延迟优化到 3 秒内，超时给"我在想"的反馈音

### M2 · 家里人试用（2 周）

- [ ] 装到 2–3 台家人的手机上
- [ ] 记录：每天用几次、问什么、哪里卡住、哪句听不懂
- [ ] 建立"失败问题清单"，按频次排序

### M3 · 迭代（持续）

- [ ] 按失败清单补术语表、改提示词、调 TTS 音色
- [ ] 加入"念给我听"（长文本朗读）和"帮我打出来"（转文字发微信）
- [ ] 视情况做方言适配（中心方言 / 和田 / 罗布泊）

## 评测方案

| 项目 | 做法 |
|---|---|
| 语料 | 20 个真实问题，覆盖天气、健康、家常、办事、内容朗读五类 |
| 评审 | 3 位维语母语者（含家里长辈）盲听，不知道哪条是 A 哪条是 B |
| 指标 | 可懂性（1–5）、自然度（1–5）、回答正确率、端到端延迟（秒） |
| 记录 | 每条回答录音留档，错误逐句标注（语序错 / 夹汉语词 / 术语错 / 答非所问） |

## 风险

1. **延迟** —— 方案 B 四跳 + 新疆到内地云往返，可能 3–5 秒。长辈对"没反应"的容忍度极低。对策：即时反馈音、流式播放、国内节点。
2. **内容安全** —— 一定会被问医疗、宗教、政策。通用模型会编。对策：分类兜底，医疗类只给"建议问医生"+ 常识，不编剂量和诊断。
3. **隐私** —— 语音要上传云端做 ASR，维语本地 ASR 目前效果差。对策：明确告知家人，不上传无关内容，不留存原始音频。
4. **方言覆盖** —— 维语分中心、和田、罗布泊等方言，家里长辈的口音可能不在训练数据里。对策：先用真实家人语音测 ASR 识别率，再定是否需要微调。
5. **成本** —— 一次对话 3–4 次 API 调用，家人高频使用约每月十几到几十元。可接受，但要设用量上限。

## 非目标

- 不做商业化、不做订阅、不拉投资
- 不做 iOS（家里没有）
- 不做多语言（只做维语 ↔ 汉语）
- 不做影视配音/字幕（那是同底层能力的另一个应用，见 [规划文档索引](notes/README.md)）
- 不做"全能助手"（不接日历、不接支付、不接智能家居）

## 与后续项目的关系

这个项目沉淀的是**维语 AI 语言层**：ASR 纠错、汉维翻译策略、术语表、TTS 音色与韵律。同一层能力可以直接复用到"中文视频 → 维语配音"这类应用上。先把对话做通，是因为它有真实用户和每日反馈，能逼着把这层能力打磨到能用。
