## D1 · 安卓原生 App

- 技术栈：Kotlin + Jetpack Compose，单 Activity，minSdk 26 / targetSdk 33+
- 录音：`AudioRecord` 16kHz / 16bit / 单声道，Opus 流式上传；录音期间必须挂**前台服务**（Foreground Service），常驻通知"Aynur 正在听"——同时解决国产 ROM 保活与"我在听"的反馈
- 交互：按住说话 + 点按模式（按一下开始 / 再按结束），两种都支持，长辈手抖也能用
- 权限与安装：一切难点发生在**安装时刻、由家人完成**——未知来源安装、麦克风授权、电池白名单、设置城市；使用者拿到手零弹窗零设置
- 首启向导 3 步（维语大字按钮）：① 同意麦克风 ② 选城市 ③ 试说一句，由安装者 5 分钟完成
- 更新：不内置自动更新，家人定期拿新 APK 重装——家人本身就是迭代渠道，符合产品节奏
- 不做：小程序、PWA（讨论后关闭，保留为将来如果安卓路线的退路）

## D2 · 纯维语语料策略

| 类型 | 数量 | 说明 |
|---|---|---|
| 纯维语核心问题 | 15 题 | 天气 / 健康 / 家常 / 办事 / 朗读 各 3 题 |
| 方言梯度 | 按家人实际口音 | 中心 / 和田 / 罗布泊方言各录若干，以家里长辈口音归属为准 |
| 汉维混说抽查 | 5 题 | 药名、微信、"交社保"等必然漏进来的词 |

- ASR 通过线：**纯维语 WER < 10%；混说抽查 WER < 20%**
- 录音条件必须真实：客厅电视背景声、真机麦克风、长辈真实语速（慢、停顿多）

## D3 · 问候与天气

- **打开问候**：App 本地判断"当天首次打开 + 时间段"，服务端生成维语问候模板，TTS 结果按文本缓存
- **天气**：不做 GPS（省权限/省电/省隐私顾虑），**安装者首次设置城市一次**，服务端调免费天气 API（心知 / 和风免费版对单用户够用），早上问候里带一句天气摘要
- **不推送**：一切主动都发生在"打开的那一刻"
- 问候/天气/超时/重说的话术模板需母语者校对后定稿（见 [persona.md](persona.md)）

## D4 · 成本结构（50 元/月红线）

| 项 | 月成本 | 备注 |
|---|---|---|
| 轻量云 2C2G | 30–40 元（新客促销） | 2C1G 也够（纯转发 + SQLite），约 30 元；续费期可能 50–70，到时按真实用量决定降配/换节点 |
| ASR + TTS 用量 | 10–20 元 | 按每天 20 次 × 20 秒估算（≈ 每天 7 分钟音频）；**以 M0 询价单为准** |
| LLM | < 3 元 | 每轮几十 token，可忽略 |
| 天气 API | 0 元 | 免费版 |

压回红线的三个手段：① **TTS 缓存**（问候 / 天气 / 兜底话术全部缓存）；② **每日对话次数硬上限**（如 60 次，超限用语音温和告知"今天说得够多了，明天再来"）；③ 不升配。如果真实账单卡在 60–80 元，建议把红线放宽到 80 而不要砍功能。

## 链路决策（待 M0 盲听最终确认）

- M0 跑**四臂**：A（LLM 直出维语）/ A'（直出 + 人设提示词 + 术语表）/ B1（专用翻译模型中转）/ B2（同一 LLM 自翻中转）
- 评测分两段（**先文本、后音频**）：
  - **T0**：不录音、不合成，只比生成出来的维语文本。文本不过关的链路，不进 T1
  - **T1**：T0 的胜者做成音频链路，再做盲听
- 倾向：M1 先走 A'（人设与语气是陪伴产品的差异点），B1 用于事实类问题；最终以盲听结果为准，不预设结论
- 盲评表必含一维"**像不像家里人在说话**"：B1 的翻译模型不吃提示词，人设会被洗成书面语，这一维就是用来暴露它的
