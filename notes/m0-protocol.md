# M0 链路验证协议（一周版）

> 目标：用**真实语音 + 真实问题**决定 ASR 供应商、链路形态（A / A' / B）、TTS 模型与成本。
> 硬性退出：ASR 过不了线 → 停，回到产品层讨论交互降级，不进入 M1。

## 总览

```
第 1 天  语料采集（真机、客厅环境、长辈真实声音）
第 2 天  ASR 三供应商 WER 实测 + 询价单
第 3 天  四臂最小链路跑通（A / A' / B1 / B2）
第 4 天  盲听评测 + 延迟实测
第 5 天  TTS 五类测试 + 问候模板定稿
第 6 天  决策记录（链路 / ASR / TTS / 成本四张表）
```

## 第 1 天 · 语料采集

- [ ] 15 题纯维语核心问题：天气 ×3、健康 ×3、家常 ×3、办事 ×3、朗读 ×3（家里人实际会问的，**不要写"例句"**）
- [ ] 方言梯度：按家里长辈实际口音归属（中心 / 和田 / 罗布泊）各录若干条
- [ ] 5 题混说抽查：药名、微信、"交社保"等
- [ ] 录制条件：真机、客厅（电视开着）、长辈真实语速
- [ ] 每条标注：说话人、年龄、口音归属、时长

**产出**：`corpus/` 与一份标注表（CSV）。

## 第 2 天 · ASR 实测

- 候选：阿里云「通用-维吾尔语」（16kHz）、讯飞、Speechmatics（备选）
- 指标：**WER**（词错误率），分纯维语 / 方言 / 混说三组
- 通过线：纯维语 **< 10%**；混说抽查 **< 20%**
- 同步拿询价单：按量计费单价、免费额度、是否有并发限制
- 记录每条错误示例（漏字 / 错词 / 方言崩）

**产出**：WER 表 + 询价单。

## 第 3 天 · 四臂最小链路

- **A**：ASR → Qwen3/DeepSeek 直出维语 → TTS
- **A'**：与 A 相同，但注入人设卡（[persona.md](persona.md)）+ 术语表
- **B1**：ASR → Hunyuan-MT-7B 维→汉 → 汉推理 → 汉→维 → TTS（自托管；先用硅基流动 API 对标质量，再本地部署）
- **B2**：ASR → LLM 翻汉 → LLM 回答 → LLM 翻维 → TTS（同一 API 三次调用，省供应商）
- 最小实现：FastAPI 后端 + 命令行调用即可，**不做 UI**；每臂记录每跳耗时

**产出**：每臂 20 题完整录音（80 条）。

## 第 4 天 · 盲听评测

- 评审：3 位维语母语者（含家里长辈），不知道 A / A' / B 的对应关系
- 维度（1–5 分）：可懂性、自然度；另记：回答正确率、端到端延迟（秒）
- 错误逐句标注：语序错 / 夹汉语词 / 术语错 / 答非所问 / 乱编
- 打乱顺序盲评，最后再揭盲

**产出**：评分表 + 错误清单（按频次排序，直接进 M2 的失败问题清单）。

## 第 5 天 · TTS 测试

- 模型：`qwen3-tts-uyghur`（基线）vs `SLED-TTS-Uyghur-UAS-0.2B`（克隆）
- 五类测试句：安慰句 / 疑问句 / 祈使句 / 数字（价格、时间）/ 药名（汉维混合）
- 通过线：可懂性 ≥ 4；自然度 ≥ 3（v1 不苛求）
- 问候/天气/超时话术**定稿并校对**后交 TTS 合成并缓存
- 记录：SLED 克隆需家人本人语音授权，且单次合成上限 20 秒 → 长文本朗读要切块（M3）

**产出**：五类合成样本 + 打分 + 定稿话术。

## 第 6 天 · 决策记录

四张表 + 一个结论，写进 [decisions.md](decisions.md)：

| 表 | 内容 |
|---|---|
| 链路表 | A / A' / B 盲听得分与延迟，选定 M1 主线 |
| ASR 表 | 三供应商 WER + 单价，选定供应商 |
| TTS 表 | 两模型五类得分，选定基线 + 是否启用克隆 |
| 开销表 | 记录选定组合的实际成本（**不设上限**，只用于判断性价比） |

**退出判定**：ASR 纯维语 WER > 15% 或盲听可懂性 < 3.5 → 暂停写代码，先解决识别与可懂性。

## 通过线汇总

| 项 | 通过线 |
|---|---|
| ASR 纯维语 WER | < 10%（硬线 15%） |
| ASR 混说 WER | < 20% |
| 盲听可懂性 | ≥ 4.0 |
| 盲听自然度 | ≥ 3.0（v1 不苛求） |
| 延迟 | A ≤ 3.5s；B ≤ 6.0s（可接受上限） |
| TTS 可懂性 | ≥ 4.0 |
| 成本 | 仅记录，不设通过线 |
